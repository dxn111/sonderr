Privacy & safety

Data, permissions, and safety boundaries.

Sonderr is designed to keep your workspace local and make access visible. This is a practical product notice, not legal advice.

Local-first behavior

  • Sessions, settings, enabled skills, and provider keys are stored locally.
  • When you configure a provider and send a task, the task and attached context may be sent to that provider.
  • Review the provider’s own terms and minimize sensitive data.
  • Use the narrowest tool permission that lets you finish the task.

Required security updates

  • Starting with v1.5.10, the standard managed install checks the official GitHub Releases endpoint at launch. GitHub sees your IP and ordinary request metadata; Sonderr compares versions locally and sends no version, prompt, workspace file, provider setting, or credential.
  • A newer stable release blocks use until that exact release is installed and the restarted app verifies its version. The screen has no skip option.
  • If the check cannot reach GitHub, the managed app stays locked and offers retry. Development source checkouts are exempt and are never overwritten.
  • The updater fetches source and dependencies from GitHub over HTTPS. Release tags are not cryptographically signed by the updater; review source if your threat model requires signed artifacts.

Safety boundaries

  • Sonderr must not help create, obtain, or distribute child sexual abuse material.
  • It must not help build weapons or explosives, enable violence, or facilitate serious wrongdoing.
  • It should protect credentials, avoid silent changes, and distinguish suggestions from actions it actually performed.
  • No automated safeguard is perfect. Stop using unsafe output and report it with safe diagnostic details.

Private safety contact

For a sensitive issue, DM Dani through Discord. If Discord is unavailable, use X to ask for a private contact path. Never send illegal material, secrets, or victim data.
